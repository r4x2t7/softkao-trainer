## 0. 结论速览

1. **题库必须自建**：能找到的公开软考题库，100% 是商业题库的二次聚合（`ruankaodaren/ruankao` 的 README 自述"最新最全免费题库"，实际内容来自付费机构库）。可用价值 = **考点分布与字段结构**，不是题目本身。
2. **法规与标准是唯一可放心引用的事实源**：全国人大网、国家法律法规数据库、中国政府网、国家标准全文公开系统，条文属公开领域事实，可引用条款要点。
3. **AI 解析默认走 OpenAI 兼容接口**：DeepSeek / 智谱 GLM / 阿里百炼 / SiliconFlow / Kimi / 火山方舟均可直连，App 只需一套 BaseURL + Key + Model 配置。
4. **离线兜底用"题库预生成"**：本地跑一次批处理把 `aiExplanation` 写回 JSON，随题库分发，零网络、零 Token 成本。
5. **题目更新通道用 GitHub raw**：`https://raw.githubusercontent.com/<owner>/<repo>/main/question-bank/index.json`，App 侧按 `index.json → vN.json → sha256 → 逐题校验` 流程增量合并。

## B. AI 解析方案对比

### B.1 五个可选方案

| 方案 | 模型/接口形态 | 可离线 | 质量 | 成本 | 适合场景 | 如何做题目解析 |
|---|---|---|---|---|---|---|
| **① 纯题库预生成**（推荐默认） | 无运行时模型；解析作为 `aiExplanation` 字段随 JSON 分发 | ✅ 完全离线 | 中高（可人工复核后固定） | 一次性 Token 成本，之后 0 | 默认体验、考场前无网环境、CI 可校验 | 批处理脚本对每题调用模型 → 结果写回 JSON → 人工抽检 → 版本化提交 |
| **② 云端 OpenAI 兼容 API** | BaseURL + Key + Model，POST `/v1/chat/completions` | ❌ | 高（旗舰模型推理链完整） | 按 Token 计费，单次解析约 ¥0.01~0.05 | 用户已配置 Key 的"深度解析"按钮 | App 侧组装 prompt（见 B.2），流式返回，失败回落到题库自带 `explanation` |
| **③ 国内直连云模型** | 同上，DeepSeek/GLM/百炼/SiliconFlow/Kimi/方舟 | ❌ | 中高，DeepSeek-R1 推理型在计算题上尤强 | 最低（DeepSeek 约 ¥2/M tokens 量级） | 国内网络环境、性价比优先 | 同 ②；BaseURL 默认填 DeepSeek `https://api.deepseek.com` |

```text
你是中国计算机技术职业资格网（软考）中级考试的资深辅导老师，正在为一道【{exam_name}】题目撰写解析。

【结论】1 句话直接点明正确选项及其含义。
【依据】引用该题所依据的知识点、公式、条款或标准（写清名称与要点，不要编造条款号）。

题目信息：

附加约束：
```

### B.3 「题库预生成 AI 解析」的批处理建议

- **脚本**：Python 3.11 + `httpx`（同步调用 `POST {base_url}/v1/chat/completions`，`temperature=0.2`，`response_format={"type":"json_object"}`），单文件 `tools/gen_ai_explanations.py`，输入 `question-bank/<exam>/vN.json`，输出 `question-bank/<exam>/vN.analysis.json`。
- **可重复**：
  1. 记录 `model`、`base_url`、`prompt_version`、`temperature`、`seed` 到输出文件的 `meta` 段；
  2. 解析结果以 `sha256(stem + options + answer + prompt_version)` 为键，命中缓存则不重复调用，保证**同输入同输出**；
  3. 失败项重试 3 次（指数退避），仍失败则跳过并在报告里列出，**不让坏数据污染题库**；
  4. 生成后跑一次 schema 校验（`explanation` ≥20 字、`aiExplanation` 非空且 150-300 字）。
- **可版本化**：解析不单独建分支，而是随题库版本走 `v1.json → v2.json`；`index.json` 的 `sha256` 覆盖整个文件，App 侧校验失败即拒绝导入。
- **人工闸门**：PR 模板要求标注"解析由哪个模型生成"；CI 里加一条"随机抽 10 题人工确认"的 checklist 条目。计算题（挣值、关键路径、码率容量）建议**人工重算一遍**再入库。
- **成本估算**：120 道题 × 约 800 token × ¥2/M ≈ ¥0.2 一次性成本；重跑全库也在 1 元以内。**这是"预生成"最大的说服力：把 Token 成本变成一次性支出。**

## D. 结论与落地建议（可直接执行）

1. **默认 AI 方案 = 纯题库预生成（方案①）**。种子题库的 `aiExplanation` 用批处理脚本离线生成并随 JSON 分发；App 内"AI 解析"按钮默认读本地字段，**未配置任何接口也不会崩**（符合验收标准 5）。
2. **联网解析默认 BaseURL 用 DeepSeek `https://api.deepseek.com`**（国内直连、OpenAI 兼容、401 实测在线、单价最低），并在设置页预置 6 个可切换预设：DeepSeek / 智谱 GLM / 阿里百炼 / SiliconFlow / Kimi / 火山方舟，全部只需 BaseURL + Key + Model 三字段。
3. **题库更新通道固定为 GitHub raw**：`https://raw.githubusercontent.com/<owner>/<repo>/main/question-bank/index.json`（可配 `main`/`master` 分支）；流程严格按 schema §6：`index.json → 比较 version → 拉 vN.json → sha256 校验 → 逐题校验 → Room 事务 upsert`，并保留"本地文件导入"兜底。
4. **错题间隔重做取 1/3/7/15 天**：1 天=次日即纠错（短时记忆仍有痕迹），3 天=跨越一个工作记忆周期，7 天=进入长期记忆门槛，15 天=抗遗忘曲线的二次巩固。这是 Anki/SM-2 的简化版，成本低、可解释；如二期升级再接 FSRS。
5. **掌握度口径用 `streak` + 历史正确率双条件**（未掌握=streak 0 或正确率<50%；模糊=streak 1-2；已掌握=streak≥3 且正确率≥80%），与错题本共用同一份状态，不要做两套。
6. **题库社区协作门槛要低**：贡献者只需改 JSON 提 PR，CI 跑 schema 校验（id 唯一、answer⊆options、explanation≥20 字、source 非空且含"改编自/自编"字样）——**`source` 字段做格式校验是版权合规的第一道闸门**。
7. **案例题单独建模**：本题库采用 `type=case` + `caseStudy` + `caseId` + `subQuestions[{q,answer}]`，`options` 用 A/B/C… 承载小问题干、`answer` 列出全部小问 key，App 端需对 `case` 类型走独立渲染分支，不按选择题渲染。
8. **竞品对标后的取舍**：做"练习模式矩阵 + 章节树 + 答题卡 + 错题间隔重做 + 倒计时模拟卷 + 本地通知 + 连续打卡"；**不做**账号体系、内置商城、排行榜社交、拍照搜题（二期候选）。
9. **离线优先的边界**：题库更新、AI 解析均为"可选联网增强"，任何网络失败只提示不阻断；数据（作答/错题/收藏/设置）全部本地存储，接口地址与 Key 只存 DataStore 本地，不上传第三方。
10. **真题回忆版只作"考点雷达"**：每次出题前扫一眼 CSDN/掘金的近期回忆帖，提取考点关键词更新到 `knowledgePoint` 标签体系，**题面一律自编**。

## E. 风险与版权提示

### E.1 绝对不能直接抓取进题库的来源

| 来源 | 为什么绝对不能 |
|---|---|
| 希赛网校 / 希赛软考 App、软考通 App、信管网 App、软考达人 App、课课家、环球网校、233网校、羊驼考试、虎题 | **商业机构付费题库**，题目与解析受著作权保护；抓取即侵权，且违反 ToS；机构已普遍加签名/验证码/登录态反爬 |
| CSDN / 掘金 / 博客园 的真题回忆帖 | 真题原文的二次传播，权利归属不清；作者可能已构成侵权。**可读不可抄** |
| `ruankaodaren/ruankao` 仓库中的题目 JSON | 仓库代码是 MIT，**但题目内容未声明授权**，且自述为"全免费软考题库"，实质是商业题库聚合；仓库体积 800MB+、README 记录每月下架/上新上万题，说明来源是抓取 |
| `devezhao/rktk-wxx` 等小程序题库 | 内容来源不可考，Apache-2.0 只覆盖代码 |
| 软考官网的样题与历年真题 PDF（bm.ruankao.org.cn 下载） | 官方样题与真题受著作权保护，**抄录进开源题库 = 公开传播侵权** |
| 清华大学出版社教材正文、例题、习题答案 | 教材是受著作权保护的出版物；可依据知识点自编改编，不可逐句抄写 |
| 任何"AI 一键把 PDF 题库转成 JSON"流程（如 pdf-exam-bank 的用法） | 转换的是"复制"，不产生新作品；**工具中立不改变侵权性质**，只可用于处理自有或已授权 PDF |
| 付费题库的解析文本 | "答案选 B，因为…"这类解析同样是受保护的文字作品，需自编 |

### E.2 可以安全做的

- ✅ 引用**法律与标准的事实性内容**：期限（20 日 / 15 日 / 30 日）、人数（评委 5 人以上单数、2/3 专家）、比例（保证金 2% / 10%）、年限（终生+50 年、20/10/15 年、商标 10 年）、标准分类与强制性要求——写成自己的话并标注法律名称。
- ✅ 依据公开考试大纲与教材**知识点自编**同类题：同一考点换载体、换数据、换设问方式。
- ✅ 研究公开题库的**字段结构、章节划分、题型比例**，用于设计本项目 schema（这是"思想"不是"表达"，受著作权法不保护）。
- ✅ 真实考场上考生回忆的**考点关键词**（如"三小时用完两小时"）——属于事实性信息，不构成对原题的复制。

### E.3 其他风险

- **反爬与稳定性**：实测 `www.cnitpmc.com` 已不可达、`233.com/ruankao/` 对脚本 403。任何"自动抓第三方题库"的功能在上线当天就会挂，且不可维护。本项目已明确排除（REQUIREMENTS-REVIEW §3.2）。
- **AI 幻觉**：AI 解析可能算错数字或编造条款号。规则：`explanation`（人工自编）永远是可信来源，`aiExplanation` 仅作增强；计算题在预生成阶段必须人工抽检。
- **模型许可**：Ollama 各模型许可不同（qwen2.5 多数 Apache-2.0，deepseek-r1 另附协议），商用前需逐个确认；个人自用本 App 风险低。
- **接口可用性**：海外 OpenAI 直连在国内不稳定且贵；App 的默认预设应面向国内可直连的模型，且允许用户自填 BaseURL 以适配自建网关/代理。
- **合规兜底**：`source` 字段强制写"改编自…（知识点）"或"自编（依据…）"，并用 CI 校验；发现侵权内容时按贡献者流程下架单题而不动他人题目。
