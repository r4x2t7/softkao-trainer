# 法条引用与法定数字审计报告

> 审计时间：2026-10-25 ｜ 范围：系统集成 1335 题 + 多媒体 1055 题，含逐知识点精讲 2195 条
> 方法：把题库与精讲里所有「第 X 条」引用和法定数字抽出来，逐条对着权威法条全文核对

## 1. 怎么做的

```bash
# 1) 抓法条正文到本地（Wikisource 的法律全文，公法条文不适用著作权法）
python tools/grab_laws.py

# 2) 抽出题库里的法条引用，并与本地法条原文对照
python tools/law_cite_audit.py            # 全部
python tools/law_cite_audit.py 专利法      # 按法筛选

# 3) 定位某个表述属于第几条
python tools/which_article.py docs/research/laws/中华人民共和国招标投标法.txt 投标保证金

# 4) 抓网页 + 只把命中的行带回终端（本地抓取，不计费）
python tools/fetch_grep.py <url|本地文件> <正则>
```

工具都在 `tools/`，法条正文不入库（`.gitignore` 已排除 `docs/research/laws/`），任何人重跑 `grab_laws.py` 都能复现。

### 2.2 引用了已废止或已删除的旧规（最危险）

**投标保证金「最高不得超过 80 万元」——早已废止。**

该上限出自早年施行的《工程建设项目施工招标投标办法》，2013 年九部委修订时删除；现行规则只有《招标投标法实施条例》第二十六条的「不超过招标项目估算价的 2%」，**不再设绝对金额上限**。

题目 si-0055 / si-1197 / si-1198 / si-1199 / si-1201 / si-1202 六道题都还在用这条旧规，其中 **si-1198 连答案都是错的**（原设定 6000 万估算价、100 万保证金，因超 80 万上限判为「不合法」；按现行法 100 万 < 120 万，应为合法）。

修订方式：把涉及绝对上限的表述全部改成「比例上限」，并把 si-1198 的场景数字改成「估算价 3000 万元、2% 即 60 万元，约定 100 万元超出比例上限 → 不合法」，答案由 C 改为 B，解析同步重写。

### 2.4 用了旧法分类

**si-0059 用的是旧《标准化法》的「四分法」**（国家/行业/地方/团体），现行标准化法是**五类**（国家/行业/地方/团体/**企业**）。原题四个选项没有一个完全正确——已重写选项 A 并同步解析。

## 4. 落地机制

修订全部集中在 `tools/fix_law_citations.py`，做的是「外科手术式」字符串替换：只改被判错的片段，其余文字一字不动。

```bash
python tools/fix_law_citations.py            # 应用
python tools/fix_law_citations.py --check    # 只体检
```

- 该脚本已接入 `tools/publish.py` 的第 1 步，所以**每次出包都会重新校验并应用**，不会因为重建题库而丢。
- 脚本幂等：已改过的地方会识别为「已应用」而不是「未命中」。
- CI 新增两道门禁：
  - `tools/check_ai_consistency.py` —— 答案与 AI 解析首句必须一致（本次 si-1198 改答案时靠它兜住）
  - `tools/kp_notes_pipeline.py coverage` —— 每个知识点都必须有精讲

## 5. 已知局限

1. 部分法条正文在 Wikisource 上是**节选**（例如《招标投标法》缺「投标保函随投标文件提交」那一款），遇到正文与记忆不符时以官方文本为准，本仓库只保留能核到原文的部分。
2. 审计只覆盖**法条引用与法定数字**，公式类（挣值、三点估算、动态范围、奈奎斯特等）另有一轮核对，未包含在本报告中。
3. 教材口径与现行法不一致时（例如商标法条号平移），本仓库以**教材口径**为准，并在报告中注明。
