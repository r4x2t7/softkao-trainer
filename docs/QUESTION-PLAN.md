## 三、题型与难度配比（每个分片内部）

| 题型 | 占比 | 说明 |
|---|---|---|
| `single` | 55%~65% | 单选，题干自洽，选项互斥 |
| `multi` | 15%~20% | 多选，正确答案 2~4 项 |
| `truefalse` | 12%~18% | 判断，answer 固定 `["√"]` 或 `["×"]` |
| `case` | 8%~12% | **仅指定分片出案例题**（见下） |

难度配比：1 简单 30%、2 较易 25%、3 中等 25%、4 较难 15%、5 难 5%。

**案例题限定分片**：SI-C、SI-D、SI-H、MD-C、MD-D、MD-G（每个分片 12~20 道案例题）。

## 四、单题硬性要求

- `explanation` ≥ 20 字，**必须给出依据或推导**，禁止"故选 B"式空解析。
- `source` 必填，写「改编自《…》第 X 章 …」或「自编（依据 …）」；**严禁抄录商业真题原文**。
- `chapter` 用统一章节名（见上表），`knowledgePoint` 细到可做知识点画像。
- `answer` 的 key 必须真实存在于 `options`；多选 ≥ 2 项；判断题 answer ∈ {√, ×}。
- `options` 的 key 从 A 起连续。
- 同一分片内题干不得重复；跨分片重复由合并脚本统一去重。

## 五、合并与发布流程

1. 各分片写入 `question-bank/<examId>/parts/<chunk>.json`（临时区，不直接进 v2）。
2. `tools/merge_banks.py` 合并：按 id 去重 → 按题干归一化去重 → 输出 `question-bank/<examId>/v2.json` → 输出分布报告。
3. `tools/validate_bank.py --all` 校验。
4. `tools/build_index.py` 重建 index.json（含 sha256）并同步 `app/src/main/assets/seed/`。
5. 版本号 +1，提交、打 tag、发 Release。

## 六、合并后必过的质量门槛

- 总题数 ≥ 2000
- 两个 examId 的题数均 ≥ 800
- 每章题数 ≥ 8（防止某章空缺或某章刷屏）
- id 唯一、题干唯一率 100%
- 单章占比 ≤ 15%
- CI 全绿
