# 需求评审纪要 · 软考刷题 App（SoftKao Trainer）

> 评审日期：2026-10-24 ｜ 状态：**通过，进入实现** ｜ 主持：mavis ｜ 记录：本文件
> 面向对象：备考「系统集成项目管理工程师」「多媒体应用设计师」（中级）的在职/在校考生。

---

## 1. 背景与问题

- 2026-10-24 参加软考中级两场考试（上午 多媒体应用设计师 · 下午 系统集成项目管理工程师）。
- 现有痛点：
  1. **题库散落**：真题回忆版、机构题库、论坛帖各在一处，题目重复、口径不一、解析质量参差。
  2. **解析弱**：多为"答案选 B，因为……"一句话，看完不知道自己为什么错。
  3. **不可离线**：考场前想刷题，机构 App 要会员、要网络、要登录。
  4. **错题没人管**：错过的题下次还错，没有掌握度、没有间隔重做。
  5. **题库更新慢**：机构题库不开放更新，App 只能整体发版。

## 2. 产品目标

> **做一个"自己的题库 App"**：题库用 GitHub 托管、可协作更新、离线可用；答错自动归集并做错题分析；解析能讲清"为什么"。

| 目标 | 可度量指标 |
|---|---|
| 离线可用 | 断网状态下全部刷题功能可用（100%） |
| 题库可协作更新 | 任意贡献者提 PR 即可新增题目，App 内一键拉取生效 |
| 错题闭环 | 错题自动入库；按知识点统计掌握度；支持错题重做与间隔重做 |
| 解析质量 | 每题解析必须含"结论 + 依据/推导"，且 ≥20 字，禁止占位 |

## 3. 范围

### 3.1 本期（MVP）做

1. **科目**：系统集成项目管理工程师、多媒体应用设计师（两个考试目录，含各科别：基础知识 / 案例分析 / 应用技术）。
2. **刷题模式**：顺序练习、章节练习、专项（知识点）练习、每日一练、错题重做、模拟卷。
3. **题型**：单选、多选、判断、案例分析（多小问）。
4. **错题分析**：错题自动入库、错因备注、按知识点/章节/难度聚合统计、掌握度标签（未掌握/模糊/已掌握）、间隔重做队列（1/3/7/15 天）。
5. **收藏与笔记**：题目收藏、自定义笔记。
6. **统计**：总做题数、正确率、连续打卡、每日/每周趋势、知识点掌握度雷达。
7. **离线题库更新**：GitHub 仓库地址 → 拉取 JSON 题库 → 校验 → 增量合并（详见 `QUESTION-BANK-SCHEMA.md`）。
8. **AI 解析入口**：可配置 OpenAI 兼容接口（本地填 BaseURL + Key + 模型），对任意题生成深度解析；未配置时回落到题库自带解析。

### 3.2 本期不做（明确排除，避免范围蔓延）

- 账号体系、登录、云同步、云端图片存储。
- 支付、会员、题库售卖。
- 自动抓取第三方题库（版权风险 + 反爬脆弱），改为**人工协作 PR**。
- 社交/排行/好友对战。
- iOS 端、Pad 专属适配（Compose 自适应已覆盖平板横屏，但不做专门优化）。

### 3.3 后续候选

- 间隔重复算法升级（Anki/FSRS）。
- 语音/图片题（拍照搜题）。
- 模拟考试成绩预测与排名参考。
- 多模块化拆分（见 §5.3）。

## 4. 竞品参考（决定做什么）

| 参考对象 | 借鉴的做法 | 我们的取舍 |
|---|---|---|
| 软考通 / 希赛 / 信管网 题库 App | 顺序练、章节练、真题、模拟卷、错题本、每日一练 | 采用其**练习模式矩阵**；不采用会员墙与内置商城 |
| 羊驼考试 / 233网校 | 章节树 + 题量统计 + 答题卡 | 采用章节树与答题卡交互 |
| Anki / Quizlet | 间隔重复、卡片自测 | 采用**错题间隔重做**（1/3/7/15 天），不做卡片自定义 |
| 虎题 / 考试类 App | 倒计时、模拟真实节奏、考前推送 | 采用倒计时与模拟卷节奏；推送改为本地通知 |
| 多邻国 / 番茄ToDo | 学习习惯养成、连续打卡 | 采用连续打卡与每日一练 |

**差异化三点**：① 题库托管在 GitHub，人人可提 PR 改题；② 完全离线可用、无需登录无广告；③ 解析带"依据"，错题按知识点做掌握度画像。

## 5. 技术选型（评审确认）

### 5.1 栈

| 层 | 选型 | 理由 |
|---|---|---|
| 语言/UI | Kotlin + Jetpack Compose + Material 3 | 声明式 UI，Material3 适配深色模式；本机 Gradle 缓存已有 androidx 依赖 |
| 架构 | 单 Activity + Navigation Compose + MVVM（`StateFlow`） | 中等规模无需过度分层 |
| 持久化 | **Room**（题目/作答/错题/收藏）+ **DataStore**（设置/更新源/token） | 离线优先；Room 事务保证题库更新与作答数据隔离 |
| 依赖注入 | 手写 `ServiceLocator`（暂不上 Hilt） | 减少 kapt/ksp 依赖与构建时间，二期再上 Hilt |
| 网络 | OkHttp + kotlinx.serialization | 只用于题库拉取，不做复杂网络栈 |
| 最低版本 | minSdk 26（Android 8.0） | 覆盖 98%+ 设备，避开老旧兼容坑 |
| 目标版本 | compileSdk 36 / targetSdk 36 | 与本机已装 platforms 一致 |

### 5.2 目录结构（单模块 + 包分层）

```
app/src/main/java/com/softkao/trainer/
├── core/model/        题目、答题记录、掌握度等领域模型
├── core/data/
│   ├── db/            Room: 实体、DAO、数据库、迁移
│   ├── repo/          题库/练习/错题/统计 Repository
│   ├── seed/          种子题库导入
│   └── remote/        GitHub 题库拉取 + 校验
├── feature/
│   ├── home/          科目/模式入口
│   ├── practice/      刷题、答题卡、解析页
│   ├── wrong/         错题本与错题分析
│   ├── stats/         统计与掌握度
│   ├── bank/          题库更新、导入导出、AI 接口设置
│   └── common/        通用组件
└── platform/          通知、本地文件、权限
```

### 5.3 演进路径

单模块起步 → 二期若出现多人并行或包体积问题，再按 `core/feature` 拆 Gradle 模块（包结构已按可拆分方式设计，迁移成本低）。

## 6. 数据模型要点

- `QuestionEntity`：题目本体（内容来自题库，可被更新覆盖）。
- `AttemptEntity`：每次作答（题目 id、选项、是否正确、耗时、答题模式、时间戳）。
- `WrongEntryEntity`：错题条目（题目 id、错误次数、最后错误时间、错因标签、备注、掌握度状态、下次复习时间）。
- `BookmarkEntity`：收藏。
- `BankSourceEntity`：题库更新源与本地版本号。

**关键约束**：题库更新只覆盖 `QuestionEntity` 内容，**绝不触碰** `AttemptEntity` / `WrongEntryEntity` / `BookmarkEntity` 中与用户学习状态相关的字段。

## 7. 掌握度算法（v1，简单可解释）

- 每题维护 `streak`（连续答对次数）与 `mastery`。
- 答对：streak+1；答错：streak=0 并入错题本。
- 掌握度标签：`未掌握`（streak=0 或历史正确率<50%）｜`模糊`（streak 1-2）｜`已掌握`（streak≥3 且正确率≥80%）。
- 错题重做按 1/3/7/15 天阶梯安排 `nextReviewAt`。

## 8. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 题库版权 | 法律风险 | 只自编/改编，`source` 必填；不抓取商业题库 |
| 题库来源不足 | 题目太少 | 种子题库我方自编 100+ 题；GitHub 社区 PR 补充 |
| 解析质量参差 | 学习价值低 | schema 强制 `explanation` ≥20 字；CI 校验 |
| 机考/大题不适配 | 案例题刷不了 | 案例题以"题干+小问+参考答案"形式呈现，并支持手写真实答案对照 |
| 无 JDK/构建环境 | 本地编译不了 | 已装 Android SDK；需授权安装 JDK 17/21 + Git |
| GitHub 拉取题库被限流 | 更新失败 | 失败可重试 + 支持本地文件导入题库 JSON 作为兜底 |

## 9. 验收标准（MVP 完成定义）

1. 全新安装、**断网**状态下，可完成：选科目 → 章节练习 → 答题 → 看解析 → 错题自动入库 → 错题重做 → 查看统计。
2. 内置题库覆盖两科，各 ≥60 题，含单选/多选/判断/案例四种题型，每题有解析。
3. 设置页填入 GitHub 仓库地址后，能拉取远端题库并增量合并，**用户的答题记录、错题、收藏全部保留**；非法题目被跳过且有提示。
4. 错题分析页能按知识点/章节聚合，标出掌握度与待复习队列。
5. AI 接口可配置，配置后对单题生成解析；未配置不崩溃。
6. 工程可在标准 Android Studio 环境（AGP + JDK 17）打开并成功构建出 Debug APK。
7. 仓库具备 README（中文）、LICENSE（MIT）、CONTRIBUTING、题库贡献指引、CI（JSON schema 校验）。
